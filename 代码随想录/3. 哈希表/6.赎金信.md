[383. 赎金信 - 力扣（LeetCode）](https://leetcode.cn/problems/ransom-note/description/)

这道题和这个题[242. 有效的字母异位词 - 力扣（LeetCode）](https://leetcode.cn/problems/valid-anagram/description/)
有异曲同工之妙，解题方法都是相同的。

这里省略暴力解法，两个for循环直接解决，时间复杂度就会变成O(n^2)。
## 哈希解法：
```c++
class Solution {
public:
    bool canConstruct(string ransomNote, string magazine) {
        int record[26] = {0};
        //add
        if (ransomNote.size() > magazine.size()) {
            return false;
        }
        for (int i = 0; i < magazine.length(); i++) {
            // 通过record数据记录 magazine里各个字符出现次数
            record[magazine[i]-'a'] ++;
        }
        for (int j = 0; j < ransomNote.length(); j++) {
            // 遍历ransomNote，在record里对应的字符个数做--操作
            record[ransomNote[j]-'a']--;
            // 如果小于零说明ransomNote里出现的字符，magazine没有
            if(record[ransomNote[j]-'a'] < 0) {
                return false;
            }
        }
        return true;
    }
};
```
- 时间复杂度: O(m+n)，其中m表示ransomNote的长度，n表示magazine的长度
- 空间复杂度: O(1)

很多人好奇为什么不直接用map？
**其实在本题的情况下，使用map的空间消耗要比数组大一些的，因为map要维护红黑树或者哈希表，而且还要做哈希函数，是费时的！数据量大的话就能体现出来差别了。 所以数组更加简单直接有效！**

- **怎么选择用哪种数据结构小技巧：**
需要存 key-value 对？（如：字母→出现次数）
    ├── 是 → 数据范围固定且小？（如26字母、0~1000）
    │       ├── 是 → 数组 ✅
    │       └── 否 → unordered_map / map
    │               ├── 需要有序？ → map（红黑树）
    │               └── 不需要有序？ → unordered_map（哈希表）
    │
    └── 否 → 只需要判断"在不在"（去重、查找）
            ├── 数据范围固定且小？ → 数组（bool标记）✅
            └── 数据范围大或不确定？ → set
                    ├── 需要有序？ → set
                    └── 不需要有序？ → unordered_set
